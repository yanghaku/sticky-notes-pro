# 持久化、保存与错误恢复

[规格入口](../product-spec.md)

## 数据职责与目录

- 全局用户偏好：标准配置目录的 `settings.json`。
- 便签内容与窗口 / 启动状态：标准数据目录的 `app.db`。
- 字体、字形、排版和预览缓存：可重建运行时数据，不是内容权威来源。

路径由操作系统标准目录确定，不硬编码用户路径。开发覆盖 `STICKY_NOTES_DATA_DIR` 时，设置、数据库与实例文件使用同一目录；空覆盖值报错。具体路径见 [paths.rs](../../src/persistence/paths.rs)。

## 全局设置

设置版本为 `schema_version: 1`，与数据库和文档版本独立：

```json
{
  "schema_version": 1,
  "note": {
    "default_width": 360,
    "default_height": 420,
    "default_theme": "white"
  },
  "editor": {
    "font_size": 16,
    "font_family": ""
  },
  "window_font": {
    "font_size": 14,
    "font_family": ""
  },
  "appearance_mode": "system",
  "scale_percent": 100
}
```

`appearance_mode` 使用 `system / light / dark`，旧文件缺省时跟随系统；字体为空表示系统默认。`window_font` 控制界面字体，与 `editor` 正文字体独立，旧文件缺省时使用系统字体 / 14 逻辑像素。设置字段独立校验，非法但可恢复的偏好使用默认值并提示，不影响便签读取。

`scale_percent` 是 50–250 的整数，默认 100。缺省兼容旧文件，非法值独立回退并提示；保存拒绝越界值，不能截断、溢出或以钳制后的展示值掩盖错误。倍率仅影响显示，不修改 Document、编辑历史或字号字段。

自定义便签配色保存在 `settings.json` 的 `note.colors.light` 与 `note.colors.dark`。每种模式使用具名字段 `yellow / green / pink / purple / blue / gray / border`，值为不含透明度的 `#RRGGBB` 字符串；不写入 `white`。旧配置缺少配色或单个字段时沿用对应内置默认值，非法单项仅回退该项并提示，不重置其他合法配色。保存拒绝非法颜色；全局配色不改变便签语义颜色 id 或内容时间。

使用同目录临时文件、写入、同步内容和平台支持的原子替换，不能直接覆盖原文件，也不能把缓冲区 flush 当作磁盘同步。失败保留原文件，设置不生效。

无法解析、顶层不是对象或显式版本非法 / 不支持时保留原文件并提示，禁止用默认设置覆盖；缺少版本字段按版本 1 兼容。缺失文件使用默认值。

设置 UI 与生效范围见[界面规范](interface.md#设置)；序列化及校验见 [settings.rs](../../src/persistence/settings.rs)。

## 便签与数据库版本

当前数据库 schema 版本为 2，SQL 与迁移的唯一实现来源为 [schema.rs](../../src/persistence/schema.rs)，本文不复制完整建表语句。

`notes` 保存：稳定随机 `id`、`document_json`、`plain_text`、`theme_id`、`created_at`、`updated_at`、可空 `deleted_at`。时间统一 UTC Unix 毫秒；颜色使用语义 id。

每张便签的 `created_at` 在首次创建时确定，此后保持不变；`updated_at` 记录最近一次内容或颜色编辑时间，保存快照保留该时间，不用后台写入时间替换。软删除和恢复保留这两个字段；界面展示见[便签列表](interface.md#便签列表)。

所有连接开启 `foreign_keys`、WAL 和 `synchronous=FULL`。数据库版本 0 的空库初始化，可识别旧库先迁移关闭记录、移除草稿引用的旧外键，再标记版本 2；未知结构拒绝接管。版本 1 事务迁移至 2；迁移失败回滚并提示，禁止删库重建；不支持的较新版本停止写入，不自动降级。

草稿不分配 `note_id` 或创建数据库 / 窗口状态记录；首次非空保存时分配不冲突的 id 并创建便签，失败保留草稿内容供重试。已有正常便签允许保存空正文，清空不等于删除；编辑保存不能通过 upsert 复活已删除 / 已彻底删除便签。

## 文档格式与投影

当前 `format_version: 1`，支持段落、有序 / 无序列表和正文加粗；示例：

```json
{
  "format_version": 1,
  "blocks": [
    { "type": "paragraph", "text": "Shopping" },
    { "type": "ordered_list", "items": [{ "text": "Milk" }] },
    { "type": "paragraph", "text": "Other" },
    {
      "type": "ordered_list",
      "continuation": true,
      "items": [{ "text": "Coffee" }]
    },
    { "type": "bullet_list", "items": [{ "text": "Apple" }] }
  ]
}
```

Paragraph 与 ListItem 存正文及可选 `bold` 区间，不存编号；旧文档缺少 `bold` 时默认为空，格式版本保持 1。区间仅描述正文，不包含生成的编号 / 圆点；搜索、复制和预览投影不输出样式标记。`continuation` 缺省 false，true 表示沿用前方有序序列。新增块类型或不兼容结构需升级格式并提供迁移，不能悄悄改变 v1。

`bold` 使用 `[{"start": 0, "end": 4}]` 表达 UTF-8 字节半开区间，范围必须有效、按位置排序且不重叠，编辑后边界对齐完整字素；旧 v1 文档中的合法字符边界区间读取时扩展到完整字素，不必补写空数组。

`document_json` 是内容权威；`plain_text` 是可重建搜索投影。非法 JSON、未知块、非法结构或不支持的版本保留原数据，便签进入错误 / 只读页面，可显示原有 `plain_text`，但不能把投影当成无损恢复。单便签损坏不阻止其他便签使用。

搜索投影用 LF 连接文本单元，保留正文空格与空段落，不包含自动编号 / 圆点。复制和列表预览使用保留标记的展示投影，不使用搜索文本代替。有效文档的旧投影失配时可重建；不支持的格式不能借重建覆盖原数据。

文档及投影由 [model.rs](../../src/model.rs) 统一定义，编辑语义见[编辑器规范](editor.md)。

## 窗口与启动状态

`window_states` 与内容同库但属应用状态：

- id、`window_type`、可空的唯一 `note_id`；便签 id 固定为 `note:<note_id>`，辅助窗口 id 固定为类型名。
- 可空的 `normal_x / normal_y`（同时存在或同时缺省，存在时须为有限数值，允许负数），有限正数 `normal_width / normal_height`。
- 可空的 `monitor_id / scale_factor`，缩放为有限正数。
- `maximized`、`always_on_top`、`updated_at`、`last_used_at`。

便签状态引用已入库便签；空草稿不能留下孤立状态。关闭后保留状态，软删除不清理状态，彻底删除按[管理规范](interface.md#彻底删除)清理。

`app_state` 最多一行（id=1），保存最后成功关闭的窗口类型、适用的便签 id 和更新时间，不保存恢复集合。关闭空草稿清除恢复目标，下次启动新草稿；历史记录中的不存在便签同样视为无有效恢复目标，不需要升级 schema。

已入库窗口的最终状态与成功关闭记录同事务保存；空草稿关闭不创建便签或窗口状态行。软删除导致关闭时遵循删除事务规则，恢复不改关闭记录。彻底删除移除匹配的整条关闭记录，之后按无有效历史启动。

## 自动保存与关闭

- 停止编辑 400ms 后提交内容保存；持续编辑目标为每 2s 向保存队列提交一次最新快照。
- 2s 是队列提交目标，不是磁盘完成或断电恢复的绝对时限。
- 同一便签按修订顺序串行处理，旧任务不能覆盖新内容；可以合并未执行旧快照。常规磁盘写入不阻塞 UI 线程。
- Document、搜索投影、颜色与 `updated_at` 同事务更新；内容时间只在内容或颜色成功改变时更新，窗口移动、内容未变的重复保存或关闭不更新时间。
- 保存状态为“未保存 / 保存中 / 已保存 / 保存失败”；当前修订成功提交才显示“已保存”，失败保留内存内容并显示重试入口。

关闭先处理 IME，再冻结编辑并等待最新修订成功；成功才释放窗口。保存失败取消关闭，保留内存内容、恢复编辑，提供重试、复制全文、明确确认后放弃修改并关闭。

最后窗口关闭同样先完成保存，并处理完队列已接受的任务，不能先退出再保存。非关键窗口状态失败应提示并保留旧状态，但不能抹掉内容或强制阻止内容已保存的窗口关闭。

正常关闭且提交成功后最后编辑应可恢复；强制终止 / 断电可丢失未提交修订。

便签、列表和设置的窗口状态写入采用 400ms debounce，持续移动 / Resize 的目标为每 2s 提交；关闭立即 flush。未完成的旧任务或队列满时保留待提交状态，失败退避后重试最新矩形，不能反复写旧快照。旧状态任务不能覆盖较新状态，激活 / 关闭的最近使用时间与内容时间分别维护；输入法组合不阻止独立保存窗口几何。

窗口状态重试成功仅清除该次失败提示，不能覆盖后来出现的内容 / 设置保存失败或其他操作错误。

## 删除事务边界

软删除、恢复和彻底删除的 UI 流程只在[便签管理](interface.md#空便签与删除)定义。
存储必须保证最终内容与删除状态原子更新、恢复只清除删除时间、彻底删除只操作指定已删除 id 并原子清理依赖。任何失败都不能造成半删除、孤立状态或旧 autosave 复活记录。
