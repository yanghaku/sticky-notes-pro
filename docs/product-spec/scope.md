# 产品目标与范围

[规格入口](../product-spec.md)

## 产品定位

轻量、本地优先的原生桌面便签应用。核心体验是多便签窗口、稳定的文字与列表编辑、自动保存、独立背景颜色、置顶和窗口状态恢复。

首发重点为 Windows、Linux X11、Linux Wayland。macOS 保持架构兼容，但不列入首发。Wayland 的基础编辑与保存必须可用；位置、置顶等限制见[窗口与平台](windows.md)。

## 当前交付范围

- 每个便签最多一个编辑窗口；便签列表与设置各最多一个窗口。
- 没有显式退出、托盘驻留或无窗口后台模式；最后窗口关闭后的退出与启动规则见[窗口规范](windows.md)。
- 普通段落、一级有序 / 无序列表、正文加粗、跨文本单元选区、纯文本剪贴板、撤销 / 重做、IME。
- 自动保存、空草稿不创建便签、已有便签允许空正文、显式软删除 / 恢复、已删除便签逐条彻底删除。
- 自定义便签标题栏、七种背景颜色、全局浅 / 深色外观、字体与字号，以及默认 100%、硬范围 50%–250% 的应用缩放。
- 三页设置和固定快捷键说明；常用便签操作快捷键，不提供自定义改键。
- 单实例、本地 SQLite、原子设置写入、版本迁移、错误隔离与失败时的数据保护。

## 暂不实现

- 真正的便签 tag 分类与列表 tag 筛选；“便签列表”不是分类窗口。
- Todo / Checkbox、嵌套列表、自定义起始编号、列表内软换行。
- 自定义 / 系统全局快捷键、搜索与 FTS、自定义排序、归档、备份与导入恢复工具。
- 更多文字格式、桌面挂件和高级窗口布局。
- 不扩展为完整 Markdown / HTML / Word / Notion 类编辑器：富文本剪贴板、表格、图片 / 附件、代码块、标题系统、复杂链接预览、云同步、协作编辑与插件系统。

这些方向实现前需另行商定交互、数据格式与验收，不提前保留尚未确认的详细设计。

## 设计原则

1. 编辑行为正确与用户数据安全优先，性能优化不得改变列表、IME 或恢复语义。
2. Editor Core 是文档、光标、选区与历史的权威来源；UI 和排版层不得各自修改文档。
3. 编号是结构派生的显示标记，不是列表项正文。
4. 每个便签的颜色、全局设置、窗口状态分别管理。
5. 平台差异集中封装；请求某项能力不等于系统已经接受。
6. 缓存可丢弃，内容不可丢弃；损坏数据不能被静默转换成空白并覆盖。
7. 先稳定当前体验，再增加功能。
